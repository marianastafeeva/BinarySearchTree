# Техническое задание: Лабораторная работа №1 (BST)

## 1. Базовое описание системы
Программа представляет собой реализацию структуры данных «Бинарное дерево поиска» (BST), расширенную до самобалансирующегося AVL-дерева. Система предназначена для эффективного хранения, поиска, удаления и обработки элементов произвольного типа (благодаря использованию шаблонов C++). Программа оснащена консольным интерфейсом для ручного тестирования, набором автоматических тестов и модулем бенчмарков для замера производительности.

## 2. Сущности системы (Классы и структуры)
В системе выделяются следующие ключевые сущности:
1. `Node<T>` (Узел) — базовая единица хранения данных.
2. `BST<T>` (Дерево) — управляющий класс, реализующий структуру и алгоритмы.
3. `Order` (Перечисление) — сущность, описывающая порядок обхода дерева.
4. `UI` (Интерфейс) — набор функций для взаимодействия с пользователем.
5. `Tests` (Тесты) — набор сущностей для автоматической проверки.
6. `Bench` (Бенчмарк) — программа для замеров скорости.

## 3. Связи между сущностями и их смысл
1. **`BST` и `Node` (Агрегация/Владение):** Дерево `BST` владеет корневым узлом (`root_`) и через него управляет всеми остальными узлами. Узлы связаны между собой указателями `left` и `right`, образуя иерархию.
2. **`BST` и `Order` (Использование):** Дерево использует перечисление `Order` в методе `Traverse()` для того, чтобы определить, в каком порядке обходить узлы (КЛП, ЛКП и т.д.).
3. **`UI` и `BST` (Зависимость):** Интерфейс `UI` принимает ссылку на объект `BST`, вызывает его публичные методы (вставка, удаление, обходы) и выводит результаты пользователю в консоль.
4. **`Tests` и `BST` (Тестирование):** Модуль `Tests` создает экземпляры `BST`, вызывает их методы и сравнивает результаты с ожидаемыми (через макросы `EXPECT_*` из Google Test).
5. **`Bench` и `BST` (Замер):** Бенчмарк создает `BST`, наполняет его большим количеством случайных чисел и замеряет время операций с помощью `std::chrono`.

## 4. Функциональные требования
Программа должна предоставлять следующий функционал:
**4.1. Управление структурой:**
* Вставка элемента (с защитой от дубликатов).
* Поиск элемента по значению.
* Удаление элемента (с обработкой трех случаев: лист, один ребенок, два ребенка).
* Автоматическая балансировка (AVL) после вставки и удаления для поддержания высоты O(log n).
* Очистка памяти при удалении дерева.

**4.2. Обходы и обработка:**
* Реализация 6 видов обхода: КЛП, КПЛ, ЛПК, ЛКП, ПЛК, ПКЛ.
* Функциональные операции: `Map` (применение функции к каждому элементу), `Where` (фильтрация), `Reduce` (свертка в одно значение).
* Прошивка дерева (Threaded Tree) для обхода без рекурсии.

**4.3. Сериализация:**
* Сохранение дерева в строку заданного формата.
* Восстановление дерева из строки с последующей балансировкой.

**4.4. Интерфейс и тестирование:**
* Консольное меню для вызова всех вышеперечисленных операций.
* Набор автоматических тестов (GTest), покрывающих граничные случаи.
* Замер времени выполнения операций на N = 10 000, 100 000, 1 000 000 элементов.

## 5. Нефункциональные требования
1. **Язык и стандарт:** C++ (стандарт C++20).
2. **Парадигма:** Объектно-ориентированное программирование (ООП) с использованием шаблонов (templates).
3. **Типизация:** Класс `BST` должен быть шаблонным и поддерживать любые типы, для которых определены операторы сравнения (`<`, `>`, `==`).
4. **Управление памятью:** Использование динамических структур на основе указателей. Утечки памяти недопустимы (RAII, деструкторы).
5. **Обработка ошибок:** Методы должны корректно обрабатывать некорректные входные данные (например, попытка удалить несуществующий элемент не должна приводить к падению программы).
6. **Производительность:** Благодаря балансировке, время поиска/вставки/удаления должно быть O(log n) даже в худших случаях. Обходы — O(n).
7. **Тестирование:** Код должен успешно проходить все 19 автоматических тестов без утечек памяти.
